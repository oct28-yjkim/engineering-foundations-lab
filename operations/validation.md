# 운영 중심 커리큘럼 개편 검증

검사일: 2026-10-04. 기존 15개 제품·도구 트랙의 학습 우선순위를 조정한 **문서 변경**입니다. LLM 논문 실험의 CPU 기본·GPU/API 선택 경로와 제품별 원리·소스 학습은 유지합니다.

## 변경 범위

- 제품별 `operations.md` 15개와 보안 공통 안내: 실제 관측 수집 경로, 지표 해석, 증상별 경쟁 가설, 조치·회복 기준.
- 공통 [학습 경로](README.md)와 [장애 보고 양식](incident-report-template.md), 각 README·커리큘럼·평가·실습 안내 연결.
- Python/SQL/YAML/HCL 등 실행 파일과 기존 검증 기록은 변경하지 않음. 기존 원리 모형은 선택 보조자료로 유지.

## 이 개편에서 수행한 검사

- 전체 Markdown 261개, 내부 링크 1,692개의 파일 경로·문서 anchor·코드 fence 검사: 오류 0.
- `git diff --check`로 공백 오류 검사.
- 기존 Python 회귀 테스트 851개 통과: MCP 151, LLM 50, IaC 82, 보안 132, MySQL 139, OpenSearch 139, NATS 158. Python 3.12.14에서 `-B -m unittest discover`로 실행. 이 수는 기존 코드 보존 확인이며 제품 운영 실습 완료를 의미하지 않음.
- 새 운영 문서의 공식 제품 문서 대조와 별도 리뷰. 지표의 gauge/counter 구분, 버전·권한·측정 단위·관측 한계, 실행 범위·복구 절차 검토.

## 실행하지 않은 것

이번 개편에서는 실제 DB/broker/검색/처리 엔진, 새로운 MCP 지연·HTTP 인증 fixture, Terraform/Terragrunt의 새 사건·run report 명령을 실행하지 않았습니다. Sentry·Supabase·Databricks의 외부 프로젝트에도 접근하지 않았습니다. 서버 기동·새 계정·유료 자원·외부 telemetry·장애 주입은 수행하지 않았습니다.

새 시나리오는 **수행 지침이며 실행 완료 기록이 아닙니다.** 제공 fixture가 없는 계측·dashboard·부하·auth/HA 환경은 학습자가 허가된 격리 환경에 별도 준비해야 합니다. 각 트랙의 기존 `validation.md`나 실습 안내에 있는 과거 실행 결과는 그 당시 명시된 범위에만 적용합니다.

운영 실습 완료는 실제 baseline 1개와 서로 다른 사건 2개의 원인 구분·조치·회복 증거로 별도 판정합니다. 환경이 없는 기록 분석·원리 학습과 실측 완료를 구분합니다.
