# 운영 실습·트러블슈팅 보고서

상태: 조사·설계 / 원리 모형 / 정제된 기존 기록 분석 / 정상 기능·관측 실측 / 사건 재현 / 조치·회복 검증. 해당하는 상태를 선택하며 실행하지 않은 단계를 성공으로 기록하지 않습니다. [기본 LAB 규격](lab-contract.md)을 따라 정상 기능에서 시작합니다.

## 1. 대상과 재현 계약

- 제품/서버/CLI/SDK/OS/edition/revision:
- 대상 endpoint·namespace의 비민감 alias, 소유자, 실행 principal의 권한 범위:
- 실제 제공 환경과 직접 구성한 부분, local/managed 차이:
- workload·seed·메시지/행 ID 집합·동시성·최대 시간·저장량·정확성 정답:
- 관측 시작/종료 시각·timezone·시계 차이·반복 횟수:
- 변경 허용 범위·중단 조건·복구/cleanup 소유권:

## 2. 정상 기능·동작·모니터링·제약

- 어떤 업무 기능인가? 합성 입력과 예상 ID/값/순서/권한, 실제 결과:
- 입력부터 저장·처리·조회/전달까지 어떤 단계로 동작하는가? 성공 응답이 보장하는 것과 보장하지 않는 것:
- 어느 단계에서 어떤 API/SQL/CLI/UI/log를 수집하는가? 단위·counter/gauge/event·수집 주기와 권한:
- 제품 자체의 제약과 이 LAB 환경의 단순화/자원 상한은 각각 무엇인가?
- 공식 자료의 출처·version/revision·확인일, 조사로 알게 된 사실과 직접 관측한 사실:
- 정상 기능의 예상과 관측이 다른 부분, 장애 재현 전 해결할 점:

## 3. 증상과 사용자 영향

관측한 증상, 최초 발생 시점, 영향을 받은 요청/작업/tenant, 최근 변경을 적습니다. 진단 전의 추측을 사실과 분리합니다.

| 신호·수집 API/SQL/UI | 유형·단위·분모·집계 구간 | 정상 기준선 | 실패 시 | 조치 후 | 누락/수집 제한 |
| --- | --- | --- | --- | --- | --- |
| 사용자 결과/정확성 | ID 집합·hash·권한 기대값 | 기록 | 기록 | 기록 | 기록 |
| 지연/오류 | latency 경계·표본 수·오류 분류 | 기록 | 기록 | 기록 | 기록 |
| 제품별 병목 상태 | counter/rate/gauge·reset 처리 | 기록 | 기록 | 기록 | 기록 |
| 자원/후속 영향 | CPU·memory·disk·backlog 등 해당 항목 | 기록 | 기록 | 기록 | 기록 |

관측하지 못한 칸에는 “미수집/권한 부족/미지원”을 쓰고 0을 채우지 않습니다. 작은 표본의 p99나 sampling된 trace로 전체 사용자의 지연을 확정하지 않습니다.

## 4. 가설과 점검 순서

| 경쟁 가설 | 맞다면 관측할 것 | 반증하는 관측 | 실제 수집 명령/증거 | 결론·확신과 한계 |
| --- | --- | --- | --- | --- |
| 원인 후보 A | 예측 | 반증 조건 | 안전하게 정제한 위치 | 채택/기각/불명 |
| 원인 후보 B | 예측 | 반증 조건 | 안전하게 정제한 위치 | 채택/기각/불명 |

원인이 되는 내부 자료구조·상태 전이·실행 계획·고정 소스 위치와 연결합니다. dashboard의 색 또는 가장 큰 숫자만으로 결론을 내리지 않습니다.

## 5. 제한된 재현·조치·되돌리기

각 단계의 시작 조건·명령·예상 변화·실제 변화·영향 대상·종료 조건을 기록합니다. 진단 읽기와 상태 변경을 구분합니다. 장애 재현은 운영 대상이 아닌 새 합성 자산에서 수행합니다. 실패 주입이 불가능하면 설계만 제출합니다.

조치 전 증거 보존 → 변경 하나 → 동일 workload 재측정 → 정확성/권한/후속 영향 검사 순서를 적습니다. 되돌리기는 데이터 복원·config 복귀·트랜잭션 rollback·단순 프로세스 재시작 중 무엇인지 구체화합니다. 하나를 다른 것의 대체로 쓰지 않습니다.

## 6. 회복 판정과 후속 예방

- 사전에 정의한 회복 기준 충족 여부와 관측 구간:
- backlog/지연/오류뿐 아니라 누락·중복·권한·데이터 hash의 유지 여부:
- 다른 원인에서도 같은 조치가 유효한지, 남은 경쟁 설명:
- 경보 후보와 false positive/false negative, runbook 개선:
- 실제로 실행하지 않은 OS·HA·cloud·보안·복구 범위:
- 원본/민감 정보 보관 정책, 정제된 증거만 Git 포함 여부:

재시작 후 잠깐 정상, 단위 테스트 PASS, health green, CLI exit 0은 각각 한 가지 관측일 뿐 종합 복구 결론이 아닙니다.
