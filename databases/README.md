# Database Labs

두 데이터베이스를 단순히 문법으로 비교하지 않고, 각 시스템이 잘 해결하는 업무 문제를 중심으로 학습합니다.

| 관점 | PostgreSQL | ClickHouse |
| --- | --- | --- |
| 대표 워크로드 | 짧은 트랜잭션, 행 단위 조회·변경 | 대량 적재, 넓은 범위의 집계·분석 |
| 저장 방식 | 행 중심 | 열 중심 |
| 일관성의 중심 | 제약 조건, 트랜잭션, MVCC | 불변에 가까운 이벤트, 비동기 병합 |
| 핵심 성능 설계 | 인덱스, 통계, 조인, vacuum | 자료형, `ORDER BY`, 파티션, part 병합 |
| 대표 질문 | “주문 한 건을 안전하게 변경하는가?” | “수억 건에서 추세를 빠르게 집계하는가?” |

## 공통 사례: 커머스 분석

두 실습 모두 사용자·주문·이벤트 데이터를 다룹니다.

- PostgreSQL: 주문과 결제를 정확하게 기록하고 동시 변경을 제어합니다.
- ClickHouse: 사용자 행동 이벤트를 빠르게 집계하고 대시보드를 제공합니다.

같은 서비스에서도 한 데이터베이스로 모든 문제를 해결하려 하지 않고, 원본 데이터의 책임과 동기화 지연 허용 범위를 명시하는 연습을 합니다.

## 완료 기준

- 워크로드를 보고 OLTP와 OLAP 중 적절한 시스템을 설명할 수 있다.
- 느린 쿼리를 실행 계획과 측정값으로 분석할 수 있다.
- 성능 개선안의 읽기·쓰기·저장 공간 비용을 함께 설명할 수 있다.
- 백업, 복구, 용량, 접근 제어, 모니터링 체크리스트를 작성할 수 있다.
