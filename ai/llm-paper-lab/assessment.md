# LLM 논문 실험 평가 기준

평가 대상은 논문을 외운 수가 아니라 **주장을 작게 만들고 구현·반례·측정으로 설명하는 능력**입니다. CPU 모형·축소 모델·GPU·API·원논문 결과 재현을 별도 범위로 평가합니다. GPU/API 미실행을 이유로 CPU 모형 평가에 실패를 주지는 않지만 원논문 재현 성공으로 바꾸어 주지도 않습니다.

## 공통 점수

선언한 범위에서 **총 80/100 이상, 각 영역 15/25 이상, 필수 게이트 모두 통과**해야 합니다. 높은 평균 점수가 데이터 누출·잘못된 분모·비밀 노출을 상쇄하지 않습니다.

| 영역 | 배점 | 최소 충족 | 높은 수준의 증거 |
| --- | --- | --- | --- |
| 정확성 | 25 | 입력·shape·확률·지표 정의와 독립 oracle 일치 | edge case·부동소수점·권한·원문 적용 범위까지 반례로 검증 |
| 원리·소스 | 25 | 식의 변수·가정과 실제 구현 지점 설명 | paper version·코드 revision·다른 구현/설정의 차이 추적 |
| 실험·반증 | 25 | 고정 fixture·baseline·한 변인·실패 조건 | ablation·음성 대조군·오염/편향·paired 불확실성·대안 가설 |
| 운영·재현성 | 25 | 환경·명령·실제 결과·예산·미실행 표시 | 제3자 재현, 자원/비용 상한, 안전한 중단, 비밀 제거와 데이터 관리 |

0점은 증거 없음, 1–14점은 중요한 오류/누락, 15–19점은 최소 조건, 20–24점은 독립 재현 가능, 25점은 적용 한계와 반례까지 설명한 경우입니다. 많은 모델을 호출한 횟수나 GPU 비용은 점수가 아닙니다.

## 필수 게이트

1. **범위 정직성:** 원논문 결과·기대값·실제값을 나누고 CPU 모형을 대규모 학습/성능 재현으로 부르지 않습니다. 미측정 값은 unknown입니다.
2. **정확성 먼저:** 손계산 또는 독립 reference와 비교하고, 의도한 결함 구현에서 검사가 실패해야 합니다. 코드가 반환한 값을 같은 코드로 정답 생성하면 부족합니다.
3. **데이터와 평가:** split·중복/누출·gold provenance·지표/분모를 고정합니다. 실패·timeout·거절을 분모에서 빼지 않습니다. test를 보고 선택했다면 그 사실을 표시합니다.
4. **공정한 비교:** baseline과 변경안을 같은 입력/예산으로 비교하거나 다른 budget을 공개합니다. 최소 하나의 ablation과 개선이 깨지는 조건을 제시합니다.
5. **권한과 비용:** 합성/허용 데이터, 검색/도구 권한, secret 무노출, GPU/API 비용·호출 한도를 지킵니다. 외부 부작용은 mock 성공으로 검증했다고 하지 않습니다.
6. **재현 패키지:** 코드·환경·논문 revision, fixture·실행 명령·원시 결과·실패 이력·한계가 있어야 합니다. 결과 조작이나 실행하지 않은 성공 로그는 즉시 미통과입니다.

## CPU 실험별 검증 범위

| 실험 | 반드시 검증할 것 | 이 결과로 주장할 수 없는 것 |
| --- | --- | --- |
| attention | masking·정규화·미래 입력 불변성과 잘못된 mask 반례 | Transformer 번역/언어모델 성능 재현 |
| lora | 병합 동치·parameter 수·초기 gradient의 작은 검산 | 실제 finetuning 품질·QLoRA 양자화 구현 |
| dpo | log-ratio margin·안정 loss·gradient 방향 | 모델 정렬·안전성·인간 선호 향상 |
| kv-cache | KV heads 등 구조별 이론 bytes·단위 | 실제 allocator·PagedAttention·GPU speedup |
| retrieval | lexical ranking·Recall/MRR/nDCG·tenant filter | DPR 학습·dense retrieval·생성 답변 정답률 |
| evaluation | paired fixture 집계·고정 seed interval·검증 실패 검출 | HELM/IFEval/RAGAS benchmark 성적·실사용자 일반화 |

제공 test suite를 통과한 뒤 학습자가 새 edge case 하나와 해당 결함을 잡는 regression test를 추가합니다. 단순히 PASS 출력을 복사하는 것은 이해 증거가 아닙니다.

## M14 최소 재현 발표

이전 모듈 중 하나를 골라 2주·24시간 안에 baseline, 변경 1개, ablation 1개, 실패 조건 1개를 묶습니다. CPU-only라면 식·작은 알고리즘의 가설에 집중합니다. GPU/API 선택 시 기존에 검증한 harness를 재사용하고 새 모델 서비스 전체를 구축하는 과제로 확대하지 않습니다.

제출은 [논문 리뷰](templates/paper-review.md), [실험 보고서](templates/experiment-report.md), 코드/테스트, 재현 명령입니다. 발표자는 “어떤 결과가 나오면 내 설명이 틀린가?”, “원논문과 무엇이 다른가?”, “품질 증가가 더 많은 계산 때문은 아닌가?”, “이 split과 지표가 놓치는 것은 무엇인가?”, “운영으로 옮기기 전에 무엇을 더 검증해야 하는가?”에 증거를 가리키며 답합니다.

전체 트랙 완료 보고서에는 14모듈의 읽기/설계/모형/실제 모델 실행 상태를 나란히 표시합니다. CPU 학습 경로 완료와 원논문 20편 전체 재현 완료는 다른 결과입니다.
