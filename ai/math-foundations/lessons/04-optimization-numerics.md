# 04. 최적화·수치 계산: 맞는 식을 안정적으로 실행하기

[시작 안내](../README.md) · [진단 Q10~Q12](../diagnostic.md) · [공식 자료](../resources.md#optimization)

최적화는 조절 가능한 숫자를 바꾸어 목적함수 값을 낮추는 과정입니다. gradient가 맞아도 한 번에 너무 멀리 가면 손실이 커집니다. 수학적으로 같은 식도 컴퓨터에서는 계산 순서에 따라 안전성이 달라집니다.

<a id="o1"></a>
## O1. 현재값에서 한 번 움직이기

미분값이 양수면 입력을 조금 늘릴 때 함수가 증가합니다. 따라서 작은 범위에서는 반대쪽으로 움직이면 줄어들 것으로 기대할 수 있습니다. gradient descent는 다음처럼 업데이트합니다.

```text
w_new = w_old - η × gradient(w_old)
η(에타)는 학습률: 한 번에 얼마나 이동할지 정하는 양수
```

`L(w)=(w-3)²/2`에서 gradient는 `w-3`입니다. 시작 `w=0`, 학습률 `0.5`이면:

```text
현재 gradient = -3
새 w = 0 - 0.5×(-3) = 1.5
이전 손실 = 9/2 = 4.5
새 손실 = (-1.5)²/2 = 1.125
```

gradient가 음수이므로 w가 증가했습니다. “항상 w를 줄인다”가 아니라 **현재 gradient의 반대 방향**으로 움직입니다. 손실이 줄었는지는 실제 새 위치에서도 계산해 봅니다.

이 식에서 최솟값은 `w=3`에 있지만 딥러닝의 모든 손실이 이런 단순한 모양인 것은 아닙니다. 한 step의 감소, 여러 step의 수렴, 별도 데이터에서의 성능 개선은 각각 다른 주장입니다.

<a id="o2"></a>
## O2. 학습률과 축별 가파름

먼저 `L(w)=a×w²/2`, `a>0`인 간단한 식을 생각합니다. gradient는 `aw`이므로 업데이트는 `w_new=(1-ηa)w`입니다. 반복할 때 크기가 줄려면 `|1-ηa|<1`, 즉 `0<η<2/a`가 필요합니다. 경계 `η=2/a`에서는 부호만 계속 바뀔 수 있어 일반적으로 수렴하지 않습니다.

숫자가 두 개이면 축마다 가파름이 다를 수 있습니다.

```text
L(x,y) = (x² + 25y²)/2
gradient = (x, 25y)
시작 (x,y) = (1,1), 손실 = 13
```

학습률 `0.1`이면 새 좌표는 `(0.9,-1.5)`, 손실은 `(0.81+25×2.25)/2=28.53`으로 증가합니다. x 방향에는 작아 보이는 학습률이 y 방향에는 너무 큽니다. 학습률 `0.04`이면 새 좌표는 `(0.96,0)`, 손실은 `0.4608`입니다.

이 **양의 대각 이차식**에서는 가장 가파른 축 25가 안정 범위 `0<η<2/25`를 제한합니다. 두 축의 곡률 비율 25는 한 축이 다른 축보다 얼마나 가파른지 나타냅니다. 여기서만 단순하게 비율을 계산한 것이며 일반 손실의 조건수를 이 숫자로 대신할 수 없습니다.

입력 단위가 천 배 다르면 관련 gradient와 곡률의 scale도 크게 달라질 수 있습니다. 데이터를 변환하거나 좌표별 이동 크기를 조절하는 이유입니다. 예를 들어 `z=5y`라는 새 좌표로 쓰면 이 목적함수는 `(x²+z²)/2`로 보입니다. 하지만 z에서 같은 학습률로 이동하고 y로 되돌리는 것은 원래 y에서 같은 학습률로 이동하는 것과 **다른 업데이트**입니다. 단순 표기 변경으로 원래 알고리즘이 저절로 좋아진 것이 아닙니다.

실제 데이터의 평균·표준편차 같은 변환값은 train 데이터에서만 구하고 검증/평가 데이터에는 그 값을 적용합니다. 전체 데이터를 보고 scale을 정하면 heldout 정보가 학습 과정에 들어갑니다. scaling이 모든 문제를 해결하거나 test 성능을 반드시 높인다는 보장도 없습니다.

<a id="o3"></a>
## O3. 큰 지수를 만들지 않고 계산하기

softmax는 여러 점수를 합계 1인 값으로 바꾸는 계산입니다. 점수 `zᵢ`의 확률은 `exp(zᵢ)/Σⱼexp(zⱼ)`입니다. 하지만 큰 양수의 exp를 직접 만들면 컴퓨터가 표현 가능한 범위를 넘을 수 있습니다.

모든 점수에서 같은 수 m을 빼면 분자와 분모가 같은 비율로 바뀌어 확률은 그대로입니다. `m=max(z)`로 정하면 계산할 지수의 입력이 모두 0 이하가 됩니다.

```text
z = [1001,1000], m = 1001
z-m = [0,-1]
확률 = [1/(1+exp(-1)), exp(-1)/(1+exp(-1))]
     ≈ [0.731059, 0.268941]
```

로그 합도 큰 지수를 먼저 계산하지 않습니다.

```text
log-sum-exp(z) = m + ln(Σⱼ exp(zⱼ-m))
              = 1001 + ln(1+exp(-1))
```

softmax에는 공통 이동값이 사라지지만 log-sum-exp에는 m을 **다시 더해야** 합니다. 정답 class가 t일 때 logits에서 직접 NLL을 구하려면 `NLL=log-sum-exp(z)-z_t`를 사용합니다. 이 예제의 두 번째 class가 정답이면 `1+ln(1+exp(-1))≈1.313262`입니다.

이 방법도 모든 비정상 입력을 고쳐 주지는 않습니다. `NaN`, 무한대 입력, 극단적인 음수 차이로 인한 작은 확률의 소실 등은 별도 계약과 한계가 필요합니다. 확률을 먼저 계산한 뒤 0이 된 값에 로그를 취하는 경로와 logits에서 NLL을 직접 구하는 경로를 구분합니다.

## 관측하며 오류를 좁히기

손실 한 숫자만 보지 말고 다음을 작은 예제에서 기록합니다.

- 업데이트 전후 parameter, gradient, 실제 이동량: 방향과 학습률이 맞는가?
- step별 손실과 유한값 여부: 감소, 진동, 증가, `NaN/inf`를 구분했는가?
- 좌표별 gradient 크기와 입력 단위: 한 축만 압도하고 있지 않은가?
- train에서 정한 변환과 heldout 평가: 누출 없이 같은 변환을 쓰는가?

gradient clipping은 gradient의 크기를 제한하는 방법입니다. momentum처럼 과거 값이 들어가는 optimizer의 실제 이동량까지 똑같이 제한한다고 일반화하지 않습니다. 이 강의의 기본 업데이트는 과거 누적 상태가 없는 단순 gradient descent입니다.

## 독립 재검산

<a id="r10"></a>
### R10 — 한 step

`L(w)=w²/2`, `w=2`, 학습률 `0.1`입니다. 새 w와 새 손실을 구하고 이전 손실과 비교하세요.

<details>
<summary>R10 해설</summary>

gradient 2, 새 값 `2-0.1×2=1.8`. 손실은 `2 → 1.8²/2=1.62`로 줄었습니다. gradient에 이미 현재 w가 들어 있으므로 업데이트 중 다시 새 w를 섞지 않습니다.

</details>

<a id="r11"></a>
### R11 — 맞는 gradient로 발산하기

`L(x,y)=(x²+4y²)/2`의 `(1,1)`에서 학습률 `0.6`으로 한 번 이동하세요. 손실을 비교하고, 이 양의 대각 이차식에서 두 축 모두 수렴하게 만드는 고정 학습률 범위를 구하세요.

<details>
<summary>R11 해설</summary>

gradient `(1,4)`, 새 좌표 `(0.4,-1.4)`. 손실은 `2.5 → (0.16+4×1.96)/2=4`. 가장 큰 곡률 4가 제한하므로 범위는 `0<η<0.5`입니다. `η=0.5`에서는 y의 부호만 바뀌어 초기 y가 0이 아니면 최솟값에 수렴하지 않습니다.

</details>

<a id="r12"></a>
### R12 — 안정적인 로그 계산

점수 `[1000,998]`의 softmax와 log-sum-exp를 큰 양수 exp 없이 구하세요. 두 번째 class가 정답일 때 NLL도 구하세요.

<details>
<summary>R12 해설</summary>

최댓값 1000을 빼면 `[0,-2]`. 확률은 `[1/(1+exp(-2)), exp(-2)/(1+exp(-2))]≈[0.8807971,0.1192029]`. log-sum-exp는 `1000+ln(1+exp(-2))≈1000.126928`. NLL은 여기서 998을 뺀 `2.126928`입니다. 확률 두 개의 합이 1인지도 검산합니다.

</details>
